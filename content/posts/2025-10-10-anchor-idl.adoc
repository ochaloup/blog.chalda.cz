What if a Solana Anchor program is created with an older version of the Anchor
and you want to interact with it using a newer version of the Anchor framework?
Or what the on-chain program does not provide a source code, but only the IDL?
With all of this may help this article.

== Anchor IDL

Anchor IDL (Interface Definition Language) is a JSON file that describes the
interface of an Anchor program. It includes information about the program's
instructions, accounts, types, and events. The IDL is used by the Anchor
framework to generate client code that can interact with the program.

The IDL is generated automatically when you build an Anchor program using the
Anchor CLI. The IDL file is typically located in the `target/idl` directory of
your Anchor project.
Any good Anchor program should have the IDL file available on-chain, so you can
fetch it using the program's public key. One way is to check the [Solana Explorer](https://explorer.solana.com/).
See for example the [IDL of Marinade Liquid Staking program](https://explorer.solana.com/address/MarBmsSgKXdrN1egZf5sqe1TMai9K1rChYNDJgjq7aD/idl).

Other way to fetch the IDL is to use the Anchor CLI:

```bash
anchor idl fetch <PROGRAM_ID> -o <OUTPUT_FILE>
```

E.g., for Marinade Liquid Staking program:

```bash
anchor idl fetch MarBmsSgKXdrN1egZf5sqe1TMai9K1rChYNDJgjq7aD | head -n 10
{
  "version": "0.1.0",
  "name": "marinade_finance",
  "instructions": [
    {
      "name": "initialize",
      "accounts": [
        {
          "name": "state",
          "isMut": true,

```

Besides the IDL file the Anchor program provides a binding for TypeScript client code.
When Anchor program is built the TypeScript bindings are generated in the `target/types` directory.
It is not available directly on-chain.

== Older versions of Anchor

Let's take a look at [Marinade Liquid Staking program](https://github.com/marinade-finance/liquid-staking-program).
It is a program that was written pretty some time ago, and it uses an older version of
the [Anchor in version 0.27.0](https://github.com/solana-foundation/anchor/releases/tag/v0.27.0).
That's a version released in March 2023 and it is dependent on Solana client v1.14.x.
The source code of the Liquid Staking program is available on-chain, but just building is a bit problematic
as the older versions of Solana client cannot be easily installed with the `curl` toolchain command.

This one just does not work

```bash
sh -c "$(curl -sSfL https://release.anza.xyz/v1.14.29/install)"

> curl: (22) The requested URL returned error: 404
```

The chance is few manual steps as the older versions of Solana client are still available on GitHub.

1. Download the Solana v1.14.29 tarball from the [Solana releases page](https://github.com/solana-labs/solana/releases/tag/v1.14.29).
   In my case, I downloaded the `solana-release-x86_64-unknown-linux-gnu.tar.bz2` file.
2. Extract the tarball to `$HOME/.local/share/solana/install/releases/<version>` directory.
   ```bash
   VERSION=1.14.29
   mkdir -p $HOME/.local/share/solana/install/releases/$VERSION
   # creating the releases directory: $HOME/.local/share/solana/install/releases/$VERSION/solana-release/
   tar xvjf solana-release-x86_64-unknown-linux-gnu.tar.bz2 -C $HOME/.local/share/solana/install/releases/$VERSION
   ```
3. Symlink the newly extracted directory
    ```bash
    rm -f $HOME/.local/share/solana/install/active_release
    ln -s $HOME/.local/share/solana/install/releases/$VERSION/solana-release $HOME/.local/share/solana/install/active_release
    ```
4. Install the Anchor version
    ```bash
    # expected the avm tool is already installed
    avm install 0.27.0
    avm use 0.27.0
    ```
5. Now you can build the Anchor program
    ```bash
    git clone https://github.com/marinade-finance/liquid-staking-program.git
    cd liquid-staking-program/
    anchor build

    ls target/idl/
    > marinade_finance.json
    ls target/types/
    > marinade_finance.ts
    ```

== Different version of Anchor and IDL

Using programs created in Anchor framework in prior versions
in programs or client applications of the current versions of Anchor
brings a significant challenges. The Anchor library is (hopefully we can say was)
deeply coupled with particular versions of Solana toolchain.
So working with program coded in Anchor in version 0.27.0 where Solana in version 1.17.x was required
was problematic when integrating CPI calls or client linking with Anchor 0.29.0.

Anchor developers strives to [address this issue](https://github.com/solana-foundation/anchor/pull/3819)
by making Anchor more independent
on Solana tooling but these difficulties still occurs especially when working with programs
coded in older Anchor versions.

Additionally, from the past to nowadays there were one substantial change of IDL format
that was [introduced in version 0.30.0](https://github.com/solana-foundation/anchor/pull/2824)
and made required in Anchor 0.30.1.
This is an issue especially to Anchor TypeScript SDK client that uses the IDL to understand
the on-chain program structure and to serialize and deserialize the instructions calls to the program.

As as on can download the IDL from chain but when it was generated in the version prior to 0.30.1
and we want to use Anchor TS SDK of the current Anchor version 0.32.0 there is a trouble of incompatibility.

=== Converting IDL to the newer format

Anchor CLI from version 0.30.1 provides an utility that is capable to convert the IDL
from the older format to the newer one. The command is `anchor idl convert`.

Running it simply with input file does not work in case the IDL format does not contain
the `metadata.address` field. This field is required in newer IDL format
and it has to be provided manually when converting the IDL.

```bash
# downloading the IDL from the chain of older version
anchor --provider.cluster mainnet idl fetch \
  MarBmsSgKXdrN1egZf5sqe1TMai9K1rChYNDJgjq7aD > /tmp/marinade_finance.json

# converting the IDL to the newer format
anchor idl convert /tmp/marinade_finance.json \
  --program-id MarBmsSgKXdrN1egZf5sqe1TMai9K1rChYNDJgjq7aD \
  -o /tmp/marinade_finance_v0.30.0.json
```

== Program Rust dependencies

The way how to overcome the issue with Anchor version incompatibilities there are two options in Rust.
Either using the third party crate [`anchor-gen`](https://github.com/saber-hq/anchor-gen) that makes possible to work
with programs of the older Anchor.
From Anchor 0.30.0 there is option to use macro [`declare_program!`](https://github.com/solana-foundation/anchor/pull/2824)
doing similar.

> **WARNING** be aware that anchor-gen code has not been audited

=== declare_program! macro

When using [the Anchor 0.30.1+](https://github.com/solana-foundation/anchor/pull/2997)
then `declare_program` is probably way to go for CPI calls within the program.``
The example usage of the macro can be found
[in the Anchor sources](https://github.com/solana-foundation/anchor/blob/d4502a6ad4e59cd29369ec7c0974a854f99164c0/tests/declare-program/programs/declare-program/src/lib.rs).

The idea is to having the [idls](https://github.com/solana-foundation/anchor/tree/d4502a6ad4e59cd29369ec7c0974a854f99164c0/tests/declare-program/idls)
alongside the program using the macro. The `declare_program!` then generates the required Rust structures
[that can be used for interacting](https://github.com/solana-foundation/anchor/blob/d4502a6ad4e59cd29369ec7c0974a854f99164c0/tests/declare-program/programs/declare-program/src/lib.rs#L5-L6)
with the program defined in the IDL.

Similarly for client calls you download the idl into specific [idls directory](https://github.com/ochaloup/test-anchor-gen/tree/59c5d072d015d4423f1b433d2d04e9f88c4c449a/declare-program-rust/idls)
and then use the macro `declare_program!` with the name of the `idl.json` file.
The [`use` directive then declares](https://github.com/ochaloup/test-anchor-gen/blob/main/declare-program-rust/src/main.rs)
what instructions and accounts are imported to the client code.

You can find the details in the Anchor documentation at chapter [Dependency Free Composability](https://www.anchor-lang.com/docs/features/declare-program).

=== anchor-gen crate

When using the prior version of Anchor then you have to either upgrade (possibly recommended)
or to use the `anchor-gen` library. That works in similar manner where a macro generates for you a Rust code
based on IDL and that can be used within your project. As difference there is created a separate "CPI crate"
for the program you want to interact with.
You can see the example of declaration of
[Marinade Liquid Staking crate](https://github.com/saber-hq/anchor-gen/tree/85658b83bdb1eca0707a336b2cd41a61ddc4805f/examples/marinade-cpi)
inside of the `anchor-gen/examples`. 

You can see that you create [the anchor-gen project](https://github.com/saber-hq/anchor-gen/blob/85658b83bdb1eca0707a336b2cd41a61ddc4805f/examples/marinade-cpi/Cargo.toml)
and places the IDL definition into [`idl.json`](https://github.com/saber-hq/anchor-gen/blob/master/examples/marinade-cpi/idl.json)
and from here the [`anchor_gen::generate_cpi_crate`](https://github.com/saber-hq/anchor-gen/blob/85658b83bdb1eca0707a336b2cd41a61ddc4805f/examples/marinade-cpi/src/lib.rs)
macro builds the Rust structures and functions that can be called from your project.

This crate is linked to your project and used. Here is example of the usage
[in Anchor Client calls](https://github.com/ochaloup/test-anchor-gen/blob/ffb9474d605ff05d09e87a94b46ffd4647162ea6/anchor-gen-rust/src/main.rs).

There could be good [to align the versions of anchor-gen](https://github.com/saber-hq/anchor-gen/blame/85658b83bdb1eca0707a336b2cd41a61ddc4805f/crates/anchor-gen/README.md#L7)
that works with particular Anchor version to make it working with your project.

== TypeScript client

When you have the IDL file you can use it in your TypeScript client code. As mentioned before it is important
to have the IDL in format aligned with the Anchor client version you are using.

On building the Anchor program the TypeScript bindings are generated in the `target/types` directory
while the IDL is in the `target/idl` directory. The on-chain program provides the IDL only.
Having types for the TypeScript client is a nice to have as it provides type safety.
When not having access to Anchor program source code you can generate the types from the IDL
using my utility [anchor-idl-to-ts](https://github.com/ochaloup/anchor-idl-to-ts).

```bash
anchor --provider.cluster mainnet idl fetch \
  MarBmsSgKXdrN1egZf5sqe1TMai9K1rChYNDJgjq7aD > /tmp/marinade_finance.json

cargo install anchor-idl-to-ts
anchor-idl-to-ts /tmp/marinade_finance.json -o /tmp/marinade_finance.ts
```

With IDL and types you can use both in your TypeScript client code.
The code that creates the Anchor program client looks similar.
The most notable difference is that for older you need to manually provide the program address
as it is not present in the IDL.

```typescript
import { PublicKey } from '@solana/web3.js'
import { IDL as MarinadeIDL, MarinadeFinance } from './types/marinade'
import { AnchorProvider, IdlAccounts, Program, Wallet } from '@coral-xyz/anchor'

const MARINADE_LIQUID_STAKE_PROGRAM_ID = new PublicKey("MarBmsSgKXdrN1egZf5sqe1TMai9K1rChYNDJgjq7aD")
const MARINADE_LIQUID_STAKE_STATE = new PublicKey("8szGkuLTAux9XMgZ2vtY39jVSowEcpBfFfD8hXSEqdGC")

export type MarinadeProgram = Program<MarinadeFinance>
export type MarinadeState = IdlAccounts<MarinadeFinance>['state']

...

const wallet = new Wallet(keypair);
const provider = new AnchorProvider(
   connection,
   wallet,
   AnchorProvider.defaultOptions(),
)
const program = new Program<MarinadeFinance>(MarinadeIDL, MARINADE_LIQUID_STAKE_PROGRAM_ID, provider)
const marinadeState = await program.account.state.fetch(MARINADE_LIQUID_STAKE_STATE)
```

=== Troubleshooting

=== missing in `idl.metadata.address` field

The `declare_program!` macro is developed to be capable to work with IDLs generated
[in the older versions of Anchor](https://github.com/solana-foundation/anchor/pull/2997/files).
But there are some pitfalls that you may encounter.

One is that when the IDL does not contain the `metadata.address` field.
When Anchor was generating the IDL in the older versions the metadata address field
was not added until the IDL was uploaded to the chain.
For manual IDL deployment it meant that the address field was not present in the IDL.
you may see an error like this:

```
error: Program id missing in `idl.metadata.address` field
  --> src/main.rs:10:18
   |
10 | declare_program!(marinade);

```

In older versions of the Anchor the IDL was not created with the `address` field by default.
The address was added to the IDL for example only at time the IDL was uploaded to the chain.

=== name collision

When working with an older IDL it may happen thet the names of accounts or instructions
collides. They were not separated that strictly as nowadays. For example, in the Marinade Liquid Staking program
there is an named set of accounts used for an instruction in the same way as `common` that generates the name collision.

```
error[E0428]: the name `__cpi_client_accounts_common` is defined multiple times
  --> src/main.rs:10:1
   |
10 | declare_program!(marinade);
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^ `__cpi_client_accounts_common` redefined here
   |
   = note: `__cpi_client_accounts_common` must be defined only once in the type namespace of this module
   = note: this error originates in the macro `declare_program` (in Nightly builds, run with -Z macro-backtrace for more info)
```

My resolution was to manually edit the IDL and rename the `common` instruction account set to
[`common_<suffix>`](https://github.com/ochaloup/test-anchor-gen/blob/529bdf72cf336d3f6746b6ac86ecd92b1058cb9b/declare-program-rust/idls/marinade.json#L845).
